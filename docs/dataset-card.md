# Controlled benchmark dataset card

Version: original CodeReviewLab template benchmark v1. License: repository MIT license.
Provenance: 120 original examples generated by the checked-in authoring script. No externally
sourced code, independent annotation, or real-repository sampling is claimed.

There are 30 function families: ten boundary contracts, ten None/empty contracts, and ten mutable
default contracts. Each family has two buggy and two correct examples. The second pair changes
the function name and documentation context, making 120 rows but only 30 distinct task families.
These closely related variants must not be interpreted as independent evidence of generalization.
The boundary and missing-input contracts are stated in docstrings because code alone cannot
establish the intended threshold or input domain.

The authoring pass examined the templates, bug/correct pair changes, accepted source lines, and
expected reference outputs. `author_reviewed` means this authoring pass, not human expert or
independent review. Every template contains a counterexample case; the reference execution
status is recorded separately in `validation.md`. Fixture examples are likewise author generated.

Fields: `id`, `family_id`, `provenance`, `review_status`, `split`, `function`, `buggy`,
`expected_findings` (category, accepted lines, explanation, suggested fix), and `reference_cases`.
Reference calls within one case share one function instance to expose persistent mutable defaults.

Split construction shuffles ten family indices per category with Python `random.Random(42)`;
three families per category are reserved. Development has 84 rows (42 buggy, 42 correct), test has
36 (18 buggy, 18 correct). No family crosses splits. Validation checks IDs, exact AST duplicates,
source syntax, names, ranges, labels, and family overlap. Renamed clone checks additionally protect
training against evaluation code. This does not detect every semantic clone or incorrect label.

```sh
python scripts/build_dataset.py
python scripts/build_fixture.py
codereviewlab validate-dataset data/benchmark.jsonl
```

Reproduction accepts identical existing content and refuses to replace different data. Evaluation
passes only `FunctionInput` into a reviewer; labels, IDs, accepted locations, and reference calls
are not prompt fields. Few-shot demonstrations are explicitly authored development examples;
they are not drawn from reserved test rows. Test labels remain stored locally for scoring and
must be kept out of prompt selection and training. Test prompt selection must occur before scores
are opened; the tool does not enforce organizational access control.

Training uses a separate reviewed `split=train` dataset. The four `split=fixture` cases only test
the pipeline and cannot establish training quality. Benchmark examples must never be copied into
training. Planned external training data must include verifiable provenance and licensing.

The supplied training collection contains 48 author-generated examples in 12 training-only
families (24 buggy, 24 correct; 16 examples per category). It covers clamping, closed intervals,
suffix offsets, adjacent-pair counts, optional aggregation/string joining/minimum/scaling, and
four persistent-state contracts. Labels, locations, fixes, and reference expectations were checked
in the authoring pass. No external provenance or independent annotation is claimed. All 48
examples passed isolated Docker reference checks. Exact/renamed-AST and family overlap validation
against development and test passed. These checks do not establish semantic independence across
every related concept or eliminate potential author bias. Closely related variants remain in one
family. Reproduce with `python scripts/build_training_data.py`.

Reference code is executed only with an explicitly invoked Docker workflow:

```sh
docker pull python:3.11-slim
python scripts/run_references.py data/benchmark.jsonl
```

The runner does not automatically pull images. It uses no network, a read-only filesystem,
256 MB memory, one CPU, a PID limit, dropped capabilities, and a 60-second host timeout. This is
an execution boundary for the supplied controlled examples, not a hardened sandbox for hostile
third-party code. Run only inspected data and use an image pinned by digest for archival runs.
